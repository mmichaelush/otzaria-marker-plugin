# תאימות אוצריא

## חוזה הגרסה

| | |
|---|---|
| `minAppVersion` | `0.9.97` |
| נבדק גם על | `0.9.98` |
| `sdkVersion` | `1.x` |
| גרסת התוסף | `0.9.6` |

`minAppVersion` נאכף משני הכיוונים, ולכן הערך אינו שרירותי:

- **מלמעלה** — התקנה נדחית אצל משתמש שגרסת אוצריא שלו נמוכה יותר.
- **מלמטה** — האריזה נדחית אם התוסף קורא ל-API שנוסף בגרסה מאוחרת מהמוצהר.

הערך הנכון הוא **הגרסה שבה נוסף ה-API החדש ביותר שהתוסף משתמש בו** — לא הגרסה
האחרונה שיצאה. התוסף משתמש ב-API שנוספו ב-0.9.97 (`reader.getHighlightCapabilities`,
`reader.addToolbarItem`, `feedback.report`, `fs.writeFile`,
`fonts.resolveFamilies`, `ui.exportPdf`, `ui.setUnsavedChanges`, ההקשר
`reader-highlight`, `selection.sections`, `contributes.background.entrypoint`,
`startup.keepAlive` ו-`when` על תרומה), ולכן `0.9.97`.

`ui.exportPdf` ו-`ui.setUnsavedChanges` אינן דורשות הרשאה — דיאלוג המערכת הוא
שער ההסכמה. ל-`ui.exportPdf` יש דרישה אחרת: אוצריא בודקת
`navigator.userActivation` בתוך ה-WebView, ולכן חובה לקרוא לה **ישירות מתוך
handler של לחיצה**. קריאה אחרי `await` ארוך מוחזרת ב-`error.forbidden`,
ו-`test/compatibility.test.js` אוכף את זה על מבנה הקוד.

`ui.print` **אינה** בשימוש בכוונה: היא קופצת ישירות לדיאלוג ההדפסה של מערכת
ההפעלה, בלי תצוגה מקדימה ובלי בחירת טווח עמודים. ההדפסה עוברת ב-
`window.print()`, שפותח את חלון ההדפסה של המנוע בתוך אוצריא ומכבד את כלל
`@page` שבגיליון הסגנון.

**למה לא `0.9.98`.** אין ב-0.9.98 שום API שהתוסף צריך. שני החידושים שם —
`fonts.local.read` ו-`sourceType` ב-`plugin.listInstalled` — אינם רלוונטיים
למרקר, והצהרה על `0.9.98` הייתה חוסמת התקנה אצל כל משתמשי 0.9.97 בלי תמורה.
התוסף רץ ב-0.9.98 ללא שינוי.

## מה אוכף את זה

`test/compatibility.test.js` מחזיק טבלה של כל קריאת SDK שהתוסף עושה, עם הגרסה
שבה היא נוספה וההרשאה שהיא דורשת (נגזרת מ-§ טבלת גרסאות API ב-`API_REFERENCE.md`
של אוצריא). הבדיקה נכשלת אם:

- נוספה קריאה שאינה בטבלה,
- קריאה דורשת גרסה גבוהה מ-`minAppVersion`,
- קריאה דורשת הרשאה שלא הוצהרה,
- אירוע נרשם בלי הרשאת ה-subscribe שלו,
- הוצהרה הרשאה שאף קריאה או תרומה אינה צריכה.

ב-CI, `app-version` ו-`api-reference-url` נעולים לאותה גרסה. שינוי ב-`dev` של
אוצריא אינו משנה את חוזה התאימות של ה-release הזה.

### שהוסרו — ומה חזר

| הרשאה | למה כבר לא |
|-------|------------|
| `plugin.storage.read` / `plugin.storage.write` | הרשאות בסיס מ-0.9.97 — הצהרה מיותרת ומעלה אזהרת ולידטור |
| `ui.feedback` | כנ״ל |
| `events.subscribe:theme.changed` | כנ״ל |
| `events.subscribe:navigation.changed` | שימש רק למחיקת בחירה שמורה, שכבר אינה קיימת |

`events.subscribe:reader.selection_changed` ו-`events.subscribe:reader.current_ref_changed`
הוסרו ב-0.9.5 וחזרו ב-0.9.6, לתפקידים צרים בהרבה מאלה שהיו להם קודם: לא מכונת
מצבים שעוקבת אחרי הבחירה, אלא החלטה בוליאנית אחת על תוכן התפריט ותווית של פקד.

`app.run_on_startup` ו-`app.background_keep_alive` היו מוחרגות בכוונה ב-0.9.5,
בהנחה שמופע רקע ארעי ימחק את הסימונים שצייר. ההנחה נכונה — ולכן 0.9.6 מצהירה
על שתיהן יחד עם `startup.keepAlive`, שמונע בדיוק את הכיבוי הזה. ראו
[ARCHITECTURE](ARCHITECTURE.md#בעלות-על-ההדגשות).

הרשאות שעדיין לא מוצהרות בכוונה: `network.*` (התוסף אינו ניגש לרשת),
`fs.folder_access` (קבצי העבודה נמצאים במרחב הפרטי, שאינו דורש הרשאה).

## תרומות דקלרטיביות

`contributes.startup` הוא מה שמאפשר לתפריט לעבוד בלי שהתוסף עלה. אוצריא קוראת
אותו ב-Dart בעליית התוכנה ואינה מריצה JavaScript.

| קטגוריה | מה מוצהר | מגבלת ה-host |
|---------|-----------|---------------|
| `contextMenuItems` | `marker-colors`, `marker-highlight-actions` | עד 2 פריטים עליונים לתוסף; `color-row` בין 1 ל-12 ערכים (התוסף שולח עד 8 צבעים ועוד מחק); עומק קינון עד 2 |
| `toolbarItems` | `marker-toolbar`, מותנה ב-`when` על `marker_toolbar_button` | עד 2 פקדים; פקד עליון חייב אייקון; עומק `when` עד 5 ועד 20 עלים |
| `shortcuts` | `ctrl+alt+h`, `ctrl+alt+m`, `ctrl+alt+j` | עד 32; חייב `command` או `contextMenuItemId` |
| `activationEvents` | `reader.current_ref_changed`, `reader.sectionContentChanged` — **בלי `app.startup`**, ראו [ARCHITECTURE](ARCHITECTURE.md#למה-appstartup-אינו-ברשימה--ואסור-להחזיר-אותו) | כל נושא דורש גם את הרשאת ה-subscribe שלו |
| `keepAlive` | `true` | דורש את `app.background_keep_alive`, שמוצגת באדום ומאושרת בנפרד |

הצבעים במניפסט הם ברירות המחדל. המנוע מעדכן אותם לצבעי המשתמש ולשפתו; ראו
[ARCHITECTURE](ARCHITECTURE.md#תפריט-ההקשר--למה-הוא-דקלרטיבי).

## התנהגות בכל הרשאה שהמשתמש עשוי לכבות

| מה כבוי | מה עדיין עובד | מה נשבר |
|---------|----------------|----------|
| `app.run_on_startup` | הכול, כל עוד לשונית התוסף פתוחה | ההדגשות נעלמות מהספרים כשהלשונית נסגרת, ולחיצה על צבע פותחת את לשונית התוסף במקום לסמן |
| `app.background_keep_alive` | הכול | ההדגשות נעלמות אחרי כשלוש דקות של חוסר פעילות וחוזרות בניווט הבא |
| `app.startup_contributions` | הכול, אחרי שהתוסף נפתח פעם אחת | התפריט אינו קיים עד שהתוסף נפתח |
| `reader.highlight` | הרשומות נשמרות, נערכות ומיוצאות | הסימון אינו מצויר על הטקסט |
| `reader.toolbar` | הכול | הפקד בשורת הפקדים |
| `app.shortcuts` | הכול | קיצורי המקלדת |
| `fs.user_files.*` | גיבוי אוטומטי במרחב הפרטי | ייצוא וייבוא לקובץ חיצוני |
| `ui.create_shortcut` | הכול | הכפתורים ליצירת קיצור דרך — הם אינם מוצגים כלל |
| `app.open_url` | הכול | כרטיס "קישורים באינטרנט" — אינו מוצג כלל |

הדף מציג הודעה מפורשת על כל אחת מארבע ההרשאות הראשונות: מה לא יעבוד, למה,
והמסלול המדויק להפעלה בהגדרות. כפתור שההרשאה שלו כבויה אינו מוצג בכלל, כדי
שלא ייכשל בלחיצה.

## מגביל הקצב של ה-RPC

| | |
|---|---|
| גודל הדלי | 50 קריאות |
| היקף | דלי לכל WebView — `PluginBridgeHandler` אחד לכל מופע |
| מילוי | טוקן אחד לכל 10ms שעברו **מאז הקריאה הקודמת** |
| שארית | נזרקת בכל קריאה (`lastRefill = now`) |
| החרגה | `library.getBookContent` בלבד |
| תשובה בסירוב | `error.rate_limited`, עם `retryable: true` |

זריקת השארית היא הפרט שקובע: רצף קריאות בפער קטן מ-10ms אינו ממלא כלום, ולכן
בדיוק 50 עוברות וכל השאר נדחות — בלולאת `await` סדרתית בדיוק כמו ב-`Promise.all`.

מרקר עומד בזה בשלוש שכבות, כולן ב-`js/marker-runtime.js`:

1. **עותק מקומי של אותו דלי**, שממתין במקום להיענות בסירוב. הוא מדמה את המארח
   כולל זריקת השארית, ומתחיל ב-45 במקום 50 — כרית לסחיפה, כי `Date.now()`
   ב-WebView גס מהשעון של Dart וכי המארח גובה טוקן גם על קריאות שאיננו עושים.
2. **ניסיון חוזר ל-`error.rate_limited` בלבד.** זו התקלה היחידה שהמארח מרים
   לפני שהריץ את הקריאה, ולכן חזרה עליה בטוחה בכל שיטה. `error.timeout` אינו
   חוזר — שם העבודה אולי כן קרתה.
3. **`mapLimit` במקום `Promise.all`** על רשימה שאורכה נקבע בידי המשתמש.

`test/rate-limit.test.js` מריץ את הכול מול נמל מדויק של המגביל.

## שדרוג מגרסה 0.9.5 ל-0.9.6

- **הנתונים נשמרים.** אין שינוי בסכימה: `marker_settings` מקבל שני שדות חדשים
  (`holyNames`, `toolbarButton`) בערכי ברירת מחדל, ורשומות ההדגשה לא נגעו.
- **שתי הרשאות חדשות ורגישות.** `app.run_on_startup` ו-
  `app.background_keep_alive` מתחילות **כבויות**, ואוצריא מציגה את השנייה
  באדום. עד שהמשתמש מאשר אותן התוסף מתנהג בדיוק כמו 0.9.5, והדף מסביר בבאנר
  מה חסר ואיך להדליק.
- **הפקד בסרגל שינה תפקיד.** הוא כבר אינו פותח את התוסף אלא מסתיר ומציג את
  ההדגשות בספר הפתוח. מי שרוצה אותו כפי שהיה משתמש ב-`Ctrl+Alt+M` או
  בלשונית הכלים; מי שאינו רוצה אותו כלל מכבה אותו במסך "אודות".
- **קובצי הגופן ירדו מהחבילה.** הגופנים נטענים מאוצריא בזמן ריצה, וגודל
  ההורדה קטן בהתאם. שם הגופן שנשמר בהגדרות לא השתנה.
- **שלושה מפתחות אחסון חדשים**: `marker_toolbar_button`, `marker_revision`
  ו-`marker_muted_books`. הם אינם חלק מקובץ הגיבוי — הם מצב מקומי, לא נתוני
  משתמש.

## שדרוג מגרסה 0.9.4

- **הנתונים נשמרים.** מפתח ההגדרות (`marker_settings`) וקידומת הרשומות
  (`highlight:`) לא השתנו. `normalizeSettings` ו-`normalizeHighlight` ממלאים
  את השדות החדשים (`language`, `autoBackup`, `bookUid`, `noteHtml`, `view`)
  בערכי ברירת מחדל.
- **קבצי גיבוי ישנים נטענים.** `parseBackup` מקבל `schemaVersion: 1` לצד 2.
- **הערות ישנות נטענות כמו שהן.** רשומה עם `note` בלבד מוצגת כטקסט, ונפתחת
  בעורך העשיר עם שבירות שורה משומרות. `noteHtml` נוסף רק בשמירה הבאה.
  מגבלת ההערה עלתה מ-1,000 תווי טקסט ל-4,000, בתוספת עד 20,000 תווי markup.
- **מזהי התפריט השתנו** מ-`marker-root` ל-`marker-colors` ול-
  `marker-highlight-actions`. `removeLegacyMenuItems` מסיר את הישנים פעם אחת
  בעלייה, כדי שעדכון תוך כדי ריצת אוצריא לא ישאיר פריט יתום.
- **מגבלת חמשת הצבעים בתפריט הוסרה.** ה-host מקבל עד 12 ערכים בשורה; התוסף
  שולח עד 8 צבעים ועוד מחק, כדי שהשורה תישאר קריאה בחלונית צרה.
- **`app.js` פוצל** ל-`marker-core.js` ול-`marker-ui.js`. תוסף שהוסיף קוד
  לקובץ הישן צריך להחליט לאיזו שכבה הוא שייך.

## כללי שינוי

1. כל API חדש דורש עדכון מפורש של `minAppVersion`, של הטבלה ב-
   `test/compatibility.test.js`, ושל `app-version` ב-CI — שלושתם יחד.
2. אין להצהיר הרשאת בסיס ואין להצהיר הרשאה שאינה בשימוש; הבדיקה תיכשל.
3. `contributes.startup` ו-`marker-domain.js` חייבים להסכים על מזהי הפריטים.
4. **כל מופע מצייר, ואין לגדר ציור בבעלות.** ה-Host עושה dedup לפי
   `(ownerPluginId, highlightId)` ומצייר את האיחוד פעם אחת, ולכן עותק נוסף
   עולה קריאת RPC אחת בלבד. כל ניסיון לבחור "מי מצייר" נכשל בכל פעם שהניחוש
   היה שגוי — ואז לא צויר כלום, בלי שום שגיאה.
5. בכל מעבר מודל יש לבדוק ידנית: עלייה קרה, לחיצה לפני שהדף נפתח, ושינוי הרשאה
   תוך כדי ריצה.
