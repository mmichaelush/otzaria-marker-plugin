# תאימות אוצריא ומסלול שדרוג

## גרסת הפרסום הנוכחית

התוסף מיועד לאוצריא `0.9.96`. המניפסט, ההרשאות וקריאות ה-SDK חייבים להישאר תקינים בגרסה זו.

- `minAppVersion` נשאר `0.9.96`.
- מודל הרקע הפעיל הוא המסלול הקיים עם `app.run_on_startup`.
- ההרשאות `ui.feedback`, `plugin.storage.read`, `plugin.storage.write` ו-`events.subscribe:theme.changed` נשמרות בכוונה: הן נדרשות ב-0.9.96, גם אם הוולידטור העדכני מסמן אותן כאוטומטיות בגרסאות חדשות יותר.
- אין קריאה ל-`plugin.backgroundDone`, אין האזנה לשינוי שפת הממשק ואין שימוש ב-API שמסומן `0.9.97`.
- `test/compatibility.test.js` סורק את קריאות ה-SDK ומכשיל שינוי שמכניס method שלא נמצא ברשימת 0.9.96 המאושרת.

מקור האמת לבדיקה הוא התיעוד בתג `0.9.96+741` של מאגר אוצריא, יחד עם ה-validator של פקודת `pack-plugin`.

ב-CI מוגדר `app-version: 0.9.96` ו-`api-reference-url` נעול לתג זה. כך שינוי עתידי ב-`dev` אינו משנה את חוזה התאימות של ה-release הזה.

ה-workflow מעביר גם את מזהה הרשומה הקבוע בחנות (`otzaria-plugin-id`) מתוך דף התוסף. כך עדכון גרסה אינו תלוי ב-endpoint הדינמי שממפה את `manifest.id` למזהה הפנימי.

הוולידטור העדכני עשוי להציג אזהרות לא חוסמות על הרשאות בסיס ועל `background.html`. אלה אינן שגיאות פרסום: הרשאות הבסיס נדרשות ב-0.9.96, וסריקת ה-reachability הסטטית אינה מתחילה מ-`contributes.background.entrypoint` אף שהקובץ נבדק ונארז בפועל.

## שכבת התאימות הקיימת

`MarkerDomain.normalizeBootContext` מרכז את הנתונים שכבר מגיעים ב-`plugin.boot`:

- גרסת אוצריא ופלטפורמה.
- `locale`, שפה וכיוון טקסט עם fallback עברי המתאים ל-0.9.96.
- מצב foreground/background.
- דגלי יכולת מחושבים בלבד. הם אינם מפעילים API חדש.

`ownsLegacyRuntime` מרכז את כלל הבעלות הנוכחי. לכן מעבר עתידי למודל הפעלה אחר לא ידרוש לחפש תנאי הרשאות במקומות שונים ב-`app.js`.

ב-HTML נשארים `lang="he"` ו-`dir="rtl"`. נתוני השפה שמדווח המארח נשמרים כ-`data-host-language` ו-`data-host-text-direction` לצורכי דיבוג, אך אינם משנים את הממשק לפני שקיים קטלוג תרגום מלא.

## הכנה ל-0.9.97

הנקודות הבאות הן תכנית מעבר בלבד ואינן פעילות בפרסום הנוכחי:

1. להוסיף קטלוג תרגום מקומי ולנתב את כל מחרוזות ה-UI דרך פונקציית `t`. רק לאחר השלמת הקטלוג האנגלי אפשר להחיל את `language` ו-`textDirection` שמגיעים ב-`plugin.boot` ולהאזין ל-`settings.changed`.
2. לבחון מעבר ל-`contributes.startup` ול-`app.startup_contributions`. מנגנון הבסיס מוכר מ-0.9.96, אך אינו מופעל כעת מפני שמגש הצבעים הוא דינמי ותלוי בהגדרות המשתמש ובבחירה הפעילה.
3. אם אוצריא תאפשר מגש צבעים דינמי דקלרטיבי, להעביר את root היחיד `marker-root` למניפסט ולהשאיר ל-JavaScript רק טיפול באירוע והשלמת הנתונים. אין לרשום root שני במקביל.
4. רק לאחר העלאת `minAppVersion` והפעלת רקע עצל אפשר להשתמש ב-`plugin.backgroundDone` לסיום עבודה חד-פעמית.

## כללי שינוי

- שינוי capability מחושב אינו הרשאה להשתמש בו. כל API חדש דורש עדכון מפורש של `minAppVersion`, המניפסט, התיעוד והבדיקות.
- אין להוסיף `contributes.startup` ריק או permission שאינו בשימוש.
- בכל מעבר מודל יש לבדוק foreground בלבד, background בלבד, שינוי הרשאה בזמן ריצה והיעדר רישום כפול של `marker-root`.
